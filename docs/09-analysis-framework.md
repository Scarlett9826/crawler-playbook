# 分析框架

## 三问

1. 用户最吐槽 / 最认可什么？
2. 官方宣发点哪些奏效、哪些无用、哪些起副作用？
3. 什么内容最容易引发关注、后续可复用？

## 七个可迁移方法

### 1. 对称口径
- 吐槽只统计负面，认可只统计正面。
- 混合内容单列，并给出“计入两边”的敏感性口径。
- 每条只归一个主主题，避免重复计数。

### 2. 立场三分法
- 每个宣发点标 buy / reject / neutral。
- 按区域（国内 / X）、平台、点赞加权拆分。
- 一条内容可涉及多个宣发点，行数不能相加。

### 3. 阶段趋势
- 首发 / 实测 / 外部事件 / 长尾。
- 看负面占比是否恶化或回暖。
- 样本量要一起报，避免把小样本当趋势。

### 4. 来源分层
- 官方 / 媒体 / KOL / 普通用户。
- 媒体多为转述，不等于信任。
- KOL 是放大器，但要区分独立与合作。

### 5. 内容形式与梗
- 翻车、横评、价格金句、实测作品、技术深度、人物、教程。
- 中位点赞、评论区负面率、爆款集中度。
- 正面/负面梗的复述性对比。

### 6. 反向证据
- 主动找辩护声音、建设性反馈。
- 避免一边倒结论。
- 记录“谁在反驳、反驳什么”。

### 7. 敏感度分析
- 剔除 top1 爆款后结论是否成立。
- 剔除人物内容后产品口碑如何。
- 按条数与按点赞是否一致。

## 视频证据

- **Showcase**：自测、同题、多模型；有数字为高置信，无数字为定性。
- **KOL 评价**：分维度 + 独立性 + 证据质量。
- **官方/媒体声明**：与自测、用户口碑三方对照。
- **矛盾证据**：声明 vs 实测、实测 vs 实测、KOL vs 观众。

## 写作原则

- 先给结论，再给证据。
- 每个结论带口径与样本量。
- 不用情绪化措辞，不把“质疑”写成“事实”。
- 区分“没有数据”与“数据为负”。
