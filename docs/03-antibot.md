# 反爬与限速

## 基本原则

1. 慢一点：默认请求间隔 2 秒，重试 3 次，指数退避。
2. 少一点：每平台设置帖子/评论上限，不做全量。
3. 像人一点：真实 Chrome、正常 UA、必要时 CDP 接管已登录浏览器。
4. 不硬刚：遇到验证码就人工过，不尝试绕过。

## 各平台要点

| 平台 | 主要风控 | 对策 |
|---|---|---|
| 小红书 | 滑块、xsec_token、频控 | 扫码登录；详情带 `xsec_source`；降低并发 |
| 抖音 | 扫码后手机号验证、视频直链时效 | 人工完成验证；转写尽快 |
| B站 | 评论接口分层、频控 | 一级/二级评论分开抓；详情补抓 |
| 知乎 | 登录态、搜索排序 | 登录后搜索；控制翻页 |
| 微博 | 游客频控、评论接口 | 先登录；热门评论接口限量 |
| 微信公众号 | 搜狗验证码、跳转链 | 真实浏览器；人工过验证码 |
| X | GraphQL 频控、登录墙 | 固定 Cookie；滚动间隔 ≥2s；失败退避 |
| YouTube | 云 IP 封禁、年龄/地区限制 | 住宅代理；失败记录并跳过 |

## 代理

`.env` 支持：

```
HTTP_PROXY=
HTTPS_PROXY=
NO_PROXY=localhost,127.0.0.1
```

代理只在必要时开启；静态代理容易被封，优先住宅轮换。

## 失败处理顺序

1. 降速（间隔 ×2）。
2. 检查登录态。
3. 换时间段。
4. 换代理。
5. 记录失败 ID，下一轮补抓。

不要连续重试同一请求超过 3 次。
